## Identity and separate influences

| Data | Lifetime | Responsibility |
| --- | --- | --- |
| Driver definition | Authored, stable ID | Name, portrait reference, base abilities, aggression and patience; independent of car/body/livery |
| Learned ability | Saved per driver | Later teammate development; initially zero gained ability |
| Track familiarity | Saved per driver/layout | Later knowledge of that layout, distinct from ability; initially explicit fixed familiarity for tests |
| Race form | One race, seeded | Small coherent execution variation; separate from driver identity and car performance |
| Corner execution | One declared corner opportunity | Bounded, smoothly applied deviation; no fresh steering noise each physics tick |
| Runtime state | One race | Intent, current execution event and recovery; cannot alter equipment or earned progress |

The five ability names from the existing plan remain useful: line judgement, braking judgement, car control, racecraft and consistency. Only the first slice's active traits should be shown as implemented capabilities. Do not invent distinct behaviour for display-only attributes. Aggression means willingness to choose a viable contested move; patience means preparing/waiting for a better opportunity. Neither is a synonym for incompetence or permission to ram.

## First behaviour: braking judgement

Vary the **usable braking estimate in speed planning**, keeping actual braking force and traction authoritative. The current backward speed pass uses a0.75 planning fraction; the neutral profile must retain that exact calculation. A less accurate/cautious judgement can use an earlier braking plan, expressed as a smaller usable planning fraction. An initial deterministic ladder of0.55/0.65/0.75 is a test hypothesis, not a final novice/expert balance promise. Apply it to the planned corner approach; do not cap attainable speed or throttle on an unconstrained straight.

First prove these deterministic differences with all random effects disabled. Neutral must reproduce the retained baseline. Earlier planning should move braking entry earlier and ordinarily cost technical-sector time, without increasing real braking capability or making the driver incapable of completing the course. If this merely causes prolonged brake tapping, revise the control interaction rather than accepting lap-time separation alone. Stronger brakes must still improve the car's achievable braking behaviour under the same driver.

Do not implement later braking by pretending the car physically has more grip. Once the deterministic ladder works, an execution deviation may delay an input decision within a bounded event; the ordinary controller, emergency response and finite vehicle capabilities determine the consequence. Delay belongs to perception/decision history, never physics timestep reduction or steering teleports. Explicit mistakes remain a separate experiment after capable baseline recovery coverage.

## Consistency and form

Use recorded race seed + stable driver ID + subsystem key, with separate streams for form, corner execution and cosmetics. Use an explicit reproducible integer generator/hash; never runtime-dependent string hashes or shared Unity random draws. Reordering entrants or adding a decal draw must not change a driver's form. Changed traffic can still change outcomes and encountered opportunities.

Sample race form once. Sample corner deviations once on entering a stable authored corner ID/lap opportunity; keep the chosen value through that opportunity and blend its influence in/out. Do not resample every planning cycle, on nearest-segment jitter, or while waiting in a queue. Set bounds before the comparison batch. Start with conservative execution deviations around the declared planning estimate, and expose the actual sampled estimate/event in telemetry. The first prototype should not deliberately produce a crash.

Consistency controls the distribution's spread; average ability and car remain fixed. Race form creates a coherent good/bad day; corner deviations add smaller local variation. Do not stack both as independent speed multipliers. Use paired seeds to compare typical pace and variance; the expected finishing-position change emerges from real encounters, never a target rank.

## Later slices retained

Line judgement, car control and racecraft need their own causal manoeuvre tests before activation. Aggression/patience then choose among physically plausible opportunities with distinct pass/abort/commit behaviour. Track familiarity improves specific approach/sequence judgement, keyed by stable layout plus compatible geometry version; basic route knowledge is always supplied. Reverse layouts are distinct. Familiarity never becomes a top-speed bonus.

Teammate learning subsequently rewards meaningful completed participation and relevant experience with diminishing returns, preserving personality while ability grows. A visible level summarises learned development; it must not replace the actual ability values. No XP for idling, deliberate crash farming or repeated trivial pass farming. Save migration, geometry-change handling, recruitment, level pacing and controller UI require their own complete implementation specification before this slice is extended into the campaign.

The follow-on player-facing milestone remains all-entrant loadouts/personality preview, UI polish and adventure racing integration, including rear-grid start, exactly-once results/payment, save reload and physical DualSense review.
